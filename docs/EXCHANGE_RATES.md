# 年度汇率与来源说明

数据范围为 1920—2026 年。唯一输入数据文件是 `assets/rates/sources/historical_exchange_rates_1920_2026.xlsx`，保留用户提供的原文件字节；程序不联网更新或补查缺失报价。

## 数据与币制

- `年度汇率` 是计算依据，统一为每 1 美元兑换的当年本币数量。`实际币名`、`口径与来源`、`原始记录`、`缺失清单` 和 `来源目录` 提供计价单位、期间、原始方向、转换倍率及来源。
- 原表共有 1,284 个年份与币种栏位；合并德国代理和重复欧元后，为 1,121 条记录，其中 1,061 条可用、60 条缺失。美元每年均为恒等基准 1。
- 原始均值的倒数不等于反向逐日报价的算术平均。程序使用原表给出的年值，并保留这项说明；不重新选择统计口径。
- 2026 年为 1—8 月的月均值等权平均。官价参考、过渡币制、部分期间等提示随选中报价显示。
- 法国旧／新法郎、中国银两／银元／法币／旧人民币／新人民币、不同时期的马克及卢布分别标识。1999 年以前不提供欧元；欧元启用后的重复区域报价合并。
- 原应用的澳元、港币、韩元、墨西哥比索等未被新表收录的币种不再提供。旧模板参考表保留用于查阅，但不参与换算。

## 网页与 Excel

网页默认显示来源摘要，并可展开机构或文献、原始链接、引用文件、表内位置、原始报价、换算过程、原表来源评级和限制。评级沿用原表，不表示应用另行认证了来源。缺失报价有独立原因列表。

网页草稿从版本 2 升级到版本 3 时，保留人物资料、美元输入和可明确识别的币种。只迁移同一币制的别名；不把「袁大头」直接等同于原表中的广义银元，也不把旧金马克自动等同于帝国马克。无法对应时要求重新选择，后端不会静默改用美元。

Excel 的「货币汇率」页面顶部显示五项：当前年份 C3、原始金额 C4、原币种 C5、目标币种 C6、目标金额 C7；下方完整显示每一年的数据。算法为「金额 ÷ 原币每美元报价 × 目标币每美元报价」，同币种直接保留金额并四舍五入到两位。缺失报价或无效年份、币种、金额时，在目标金额格显示具体提示，不伪装成零。保留已有年份与币种选择，不自动改为电脑当前年份。

「人物卡」资产栏 S62（黄色格）可直接选择资产币种，消费水平、现金、其他资产和各项明细随之换算。资产汇率年份仍在「货币汇率」K1 修改，K2 改为读取人物卡 S62 的公式；K3:K8、K18:K23 保留资产报价和来源。换算器年份／币种与人物卡的资产选择独立，修改换算器不会改变资产，也不会覆盖原有美元输入。更改任一汇率年份后，如果原币种在该年失效，应从下拉框重新选择。可选范围仅为该年度已有报价的货币，不包含未收录或缺失的币种。

年度表从 A35 开始，A:T 列及第 35—1156 行直接可见、不分组折叠，保留 1920—2026 年全部 1,121 条记录和各自来源、期间、说明。顶部辅助计算仍保留：J3:K7 仅用 `;;;` 格式隐藏显示，值和公式没有删除；需要维护资产年份 K1 时，可取消隐藏第 1 行。U:V 下拉辅助数据与 X36:AE66 旧历史参考仍保持原有隐藏状态，V1 是资产匹配行，V3:V4 是换算器匹配行。公式使用 INDEX/MATCH、COUNTIF、IF 和命名范围，不使用宏、动态数组或外部数据连接。主表下拉通过 `COC7_FX_ASSET_OPTIONS` 命名范围读取资产年份对应的列表。

金额输入以美元为基准。网页及 Python 使用十进制乘法，最终金额四舍五入到两位；Excel 保留数值与公式，按相同规则 ROUND。Excel 自身采用约 15 位有效数字，极大金额的末位精度仍受 Excel 原生数值限制。

信用资产基准沿用原规则：2026 年使用 20 倍现代基准，其他年份保持历史基准。这不是逐年通胀或购买力模型。手动金额 0 与留空自动计算有不同含义。

## 更新数据和模板

`scripts/import_exchange_rates.py` 使用 openpyxl **只读**来源文件，逐项核对原表年值、原始报价方向、倍率及代理重复关系，生成 `assets/rates/annual.json`。错误、未预期的缺失或重复记录会中止导入。JSON 保留原表中保存的十进制数值文本。

`scripts/build_fx_template.mjs` 使用 `@oai/artifact-tool` 生成新增数据、输入控件和公式。`scripts/merge_fx_template.py` 只合并相关 OOXML 范围与所需样式／验证／命名范围，保留原模板图表、VML、扩展验证及其他工作表。生成前分别备份项目模板和原始模板。

合并控件须遵守工作表 XML 的节点顺序：`mergeCells`、`phoneticPr`、`conditionalFormatting`、`dataValidations`，随后才是页面和打印设置。仅通过 XML 解析或 openpyxl 读取不足以验证 Excel 兼容性；顺序错误会导致 Excel 报告 `sheet13.xml` 加载错误并修复「货币汇率」表。`tests/test_fx_template_xml.py` 检查模板和控件插入顺序，发布前还应在 Excel 中以正常模式打开，确认未进入修复模式且年份、币种下拉及换算可用。

维护环境使用 Codex 提供的 Node、Python 和库，给 `scripts/node_modules` 创建到其 Node 库目录的软链接后运行生成脚本；生产镜像不需要 Artifact Tool。先运行 `build_fx_template.mjs preview` 查看现有模板，再运行构建。合并时建议使用保存的更新前模板作为 `--template` 输入，并输出到独立临时文件。

仅升级新的换算界面时，运行 `build_fx_template.mjs calculator <保存后的模板路径>`，使用 `test-output/fx-calculator/` 下的 donor 和 manifest 调用合并脚本。此模式不重建年度数据，不重置已保存的年份、币种、美元输入或人物内容，遇到历史参考目标区域已有内容会停止。`COC7_FX_CALCULATOR_SCHEMA` 标记该布局版本。维护合并不采纳生成库的公式缓存，必须再使用 Excel／LibreOffice 真正重算并验证后才替换模板；否则可能把不支持的 HYPERLINK 缓存写为非标准错误字符串，导致 Excel 无法打开。

用户保存的新版模板可能含新的版本说明（更新说明 P3）。目录加载记录该文本，导出后精确核对而非强制清空；内容改变、缺失或被替换为公式仍会报错。源文件哈希、汇率数据版本及技能结构校验保持不变。

五项精简界面用 `build_fx_template.mjs calculator-compact <现有模板路径>` 生成 `test-output/fx-compact/` 的 donor 和 manifest，再用同一合并脚本应用。只修改指定标签、目标金额的错误提示和可见区域；顶部辅助信息隐藏保留，年度明细保持展开。打印范围仍为 A3:F7。与完整界面升级相同，涉及公式的升级必须进行原生重算后才替换模板。

已有精简模板只需恢复年度数据显示时，先运行 `build_fx_template.mjs years-visible`，再给合并脚本传入 `--annual-visible --donor test-output/fx-years-visible/visibility-donor.xlsx` 和备份输入、独立输出路径。此模式仅局部更新行列显示属性和顶部辅助格的显示格式，保留所有值、公式、缓存及其他 ZIP 部件，不重建数据表。验证正常打开、年度明细可见和导出后再替换正式模板。

`scripts/recalculate_template.py` 通过 LibreOffice 重算临时副本，只合并公式缓存。空白原模板在未填写属性时，附表 G8:L8 的比例计算已有除零状态；使用 `--baseline` 时仅保留基线中完全相同的既有公式和旧缓存，不改写这些无关公式。年度汇率区域和所有新增公式的任何错误仍会阻止生成。填写有效属性后的角色导出要求整个工作簿无公式错误。

模板以 `COC7_FX_DATA_SHA256` 命名常量记录规范化 JSON 的哈希。应用启动加载目录时核对版本，避免网页和模板使用不同的数据文件。更新模板与数据后重启服务。

固定换算公式、资产明细标签和已有模板兼容修补应在维护阶段完成，并通过导出测试验证。运行时只填写角色输入和必要格式，不再补写这些固定公式或迁移旧明细金额；使用其他模板时，即使命名版本标记相同，也须满足当前模板结构与公式要求。

## 验证与部署

2026-09-30 换算界面更新在 Windows Excel 16.0 实测正常打开、重算、保存及再打开，覆盖跨币种、同币种、零值、非法输入、缺失报价、历史币制、主表资产独立切换和导入导出。完整回归为 190 passed、14 skipped、4 subtests passed；LibreOffice 未安装，相应原生测试跳过，不视为通过。已逐项核对用户保存的内容，保留全部 14 张工作表、原生图表／VML、扩展控件及未涉及的合并与打印设置。

运行 `.venv/bin/python -m pytest -q`。测试逐项核对全部 1,284 个原表栏位，检查全部有效报价的网页／后端十进制金额一致性，并在真实 LibreOffice 中切换年度、币制与缺失选项。导出测试保留原有头像、职业、并发、结构和缓存验证。

`scripts/start-container.sh` 会为已有镜像创建带时间戳的 `coc7-card:backup-*` 标签，再构建并更新容器。若新容器无法健康启动，脚本恢复旧镜像并重新启动。也可手动将选定备份镜像标记回 `coc7-card:local`，然后执行 `docker compose up -d --no-build --wait`。默认访问地址仍为 http://127.0.0.1:8765。
